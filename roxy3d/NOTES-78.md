final's position/depth capture uses a **1.25-frame shutter**; this brief explicitly requires the
central pose with motion blur disabled. Differences remain even in part B, where **zero objects
or materials were excluded**. They cannot honestly be attributed solely to glass/rain removal.

depth with **median = 0, p99 = 0 camera-Z units**, only **0.0165413%** of codes differing
(maximum 0.00239803 Z). The required central-pose version differs at **87.3774113%** of that frame's
pixels. The old/new mismatch is therefore explicitly retained in the evidence, not called a pass.

## Geometry, camera and encoding

Loads the unchanged Brief-76 `production_A.blend` and `production_B.blend` read-only.
Their SHA-256 values match the scene hashes embedded in the delivered final's receipts.
The v8 camera, bus and car JSON are byte-identical to the delivered approved paths.
Original scene animation is evaluated with `frame_set`, preserving the already-retimed
`godot_animation_frame` hinges/curtains, doors, bus, sedan and wheels. The original renderer's
camera application is reused, with the final's JSON, sensor fit/dimensions, lens or ortho scale,
shift and clip range. The smoke camera matrices match the old receipts exactly (maximum error 0).
No camera approximation, path retiming, representation-switch interpolation or endpoint depth substitution.
All final-hold frames are rendered normally. Motion blur is explicitly off, at each central frame pose.

Cycles emits only Position and Depth passes, one sample, at native 1920x1080. Retained opaque
shaders are replaced in memory by black zero-strength emission to remove lighting work;
their geometry, modifiers, transforms and visibility stay intact. Camera-conditional sky/sign
shaders are preserved. No combined/color image is saved. Positive camera Z is calculated with
the inverse camera matrix from the Position pass, using Depth to reject missing surfaces.
The exact per-frame near/far from final `frames.json` encode with
`round((z-near)/(far-near)*65534)`; 65535 denotes no surface/clipped. Every written PNG is decoded
immediately and checked against its encoded array before its atomic receipt is committed.

  both scene startups; **14.40 s/frame per worker** during rendering,

- Peak observed GPU allocation: **3965 MiB / 6144 MiB** including the owner's other GPU use.
  Minimum Windows commit headroom with two workers: **0.81 GB**. A third worker
  needs several GB more commitment, so two workers / four CPU threads each is the measured limit.
- Estimated full job: **2–3 hours** under similar owner workload; no hours-long wait was performed.
- Eleven smoke PNGs total 3.26 MB; expected full output approximately **0.5–0.8 GB**, depending
  on the route. Current free space at note creation: **1.84 GB**.
  A worker stops before starting another frame if free space falls below 350 MB. It does not delete
  source data or owner files. If that guard fires, completed frames remain resumable.

## Restart / resume and progress

From `roxy3d`, in PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\fly\v8-depth78\launch.ps1 -Workers 2
Get-Content .\fly\v8-depth78\progress.json
Get-Content .\fly\v8-depth78\render.log -Tail 20
Test-Path .\fly\v8-depth78\DONE
Get-Content .\fly\v8-depth78\FAILED -ErrorAction SilentlyContinue
```

The launcher uses Windows `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_BREAKAWAY_FROM_JOB`,
with stdin closed and file-backed logs. It does not depend on this agent session or its terminal.
The supervisor owns a process-lifetime file lock, preventing duplicate supervisors. Workers own
disjoint odd/even stripes. Restart uses the same command and skips frames only when their recipe/
source signature, file hash and PNG decode match. A failed run can also resume with `-Workers 1`
if the owner's other applications need the memory. A restart does not require deleting any frames.
If the computer sleeps or shuts down, resume after it is awake; this does not install a boot service.

Source originals, v8 finals, `cloud/`, pages, art packs and shared code were not modified.
No cloud requests, GPU rental, computer use, commit or push. Changes are logged here rather than
in `PROGRESS.md` because Brief 78 explicitly restricts writes to this note and `fly/v8-depth78/`.

## Exclusion decisions and ambiguities

Excluded every identified transmissive/alpha-blended surface and all named rain, water and
volume effects, including procedural generators and their prototype meshes. Opaque wet roads,
roofing, frames, mullions, handles, awnings, gutters and vehicle bodies remain.
Alpha-bearing emote/stain/decal planes are excluded as transparent layers; their opaque backing
geometry remains. The list includes objects already hidden in the source, so prototype omissions
are explicit and do not suggest every listed object previously affected the picture.

Names alone are ambiguous for some retained objects: neon 'bent glass' tube bodies, opaque lamp
lenses, `Arcade CRT dark glass`, and the red `D3 extinguisher glass cabinet` have opaque source
surface materials, so they remain. Wired skylight panes and record-store display glazing are
explicit glazing and are excluded despite their opaque stylized shaders; their bars/frames remain.
The camera-only EXIT/indicator materials are opaque for primary camera rays and transparent only
for other ray types, so all five sign objects in part B remain. No unresolved excluded-object
classification is silently treated as certain: these semantic choices are stated here for review.

Conditional see-through surface, object retained: `P8 enclosing indigo cloud sky`, material
`76 camera outside transparent | P8 indigo cloud dome`. Its original outside-transparent shader
is preserved, as is the opaque inner hemisphere. The outside-face depth residual is tracked above.

The exhaustive object/material names below are grouped by kind. Machine-readable source flags,
shader reasons and exact names are also in `exclusions-A.json` and `exclusions-B.json`.
